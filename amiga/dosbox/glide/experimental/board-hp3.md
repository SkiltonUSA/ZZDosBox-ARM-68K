# Renderer through the generated HP3 converter

This test connects Xanxi's XX19d-RIX renderer to the **actual generated AMD
AXI4-to-AXI3 converter** used before PS7 HP3. XSim executes the converter and
its AMD FIFO model against behavioural RAM. It does not emulate PS7, DDR
arbitration, CPU caches or display scanout. No physical GPU or game FPS follows
from these results.

The clean, patch-prepared build passes **10 cases and 32 framebuffer checks**,
including 117,183 compared interior pixels. Both existing Verilator variants
also pass, with 64 framebuffer checks between them.

## Four-state findings

Unlike the earlier two-state simulation, XSim preserves unknown (`X`) and
undriven (`Z`) values. That exposed four problems in the candidate:

| Finding | Reproduction | Correction |
| --- | --- | --- |
| Framebuffer apply outputs were not reset | The parser remained waiting before its first memory transaction | Reset the colour, depth and stencil apply outputs |
| Pixel offsets were narrower than framebuffer address ports | Upper address bits were undriven in XSim; solid pixels were wrong and additive reads stalled | Explicitly zero-extend all six read/write pixel offsets |
| Float-to-integer rounding read bit −1 for a zero shift | Half-alpha conversion produced unknown pixels | Use zero rounding when no bits are shifted away |
| Blend registers used blocking assignments across clocked processes | A delayed-response run wrote an unknown edge pixel despite known valid inputs | Use nonblocking assignments for the blend stage registers, preserving its three-cycle pipeline |

These corrections are part of the [renderer backport](board-completion.patch),
not forced values or waived assertions in the test. The original startup timeout
and delayed-pixel failure are retained with the validation evidence.
They do not establish the cause of an earlier physical freeze or a defect in
published firmware: the failing subject was this experimental integration.

The runner also moves declarations before their first use in four simulation
copies, without changing expressions or logic. It records original and reordered
hashes. The board source remains unchanged by those syntax normalizations.

## Test coverage

The test uses five scenes: clear, solid, additive, texture and alpha. It checks
framebuffer pixels with the existing oracle, guards and texture preservation;
command contents and padding; retained batch identity; AXI3 write ID, length and
last-beat agreement; and outstanding read/write counts on both sides of the
converter before completion. Delays are applied at the RAM side of the converter.

The case matrix includes inline and DDR-fed streams, delayed responses,
cancellation, write/read errors, malformed short DDR transfers, and a deliberate
premature-drain mutation. The memory aperture checks reject unknown high address
bits as well as out-of-range addresses. Pixel files containing unknown values
fail validation, including pixels outside the oracle's interior comparisons.

| Case | Result |
| --- | --- |
| Inline: normal / delayed / cancelled | Five framebuffers pass per case |
| DDR-fed: normal / delayed / cancelled | Five framebuffers pass per case |
| Read error | Two prior framebuffers pass; completion quarantined |
| Write error | Completion quarantined |
| Short DDR transfer | Completion remains pending |
| Forced premature drain | Outstanding-transaction assertion detects the defect |

Depth rendering and long-burst splitting are not covered by these scenes.
The observed write bursts are at most four beats; this is not a claim that every
AXI4-to-AXI3 conversion mode has been tested. Digital simulation also does not
prove reset safety during an in-flight physical transaction.

## Reproduce

First prepare the renderer with `scripts/prepare_glide_board_completion.py`.
Use a board project generated by Vivado 2025.2 for the converter inputs:

```sh
python3 scripts/test_dosbox_glide_full_renderer.py \
  --upstream .context/board-completion-source --board --ordered-state \
  --hp3-generated /path/to/project.gen/sources_1/bd/zz9000_ps \
  --output .context/hp3-test --prepare-only
python3 scripts/test_dosbox_glide_hp3.py \
  --prepared .context/hp3-test --wine-prefix /path/to/existing-wine-prefix
```

The XSim runner uses the existing Windows Vivado installation through Wine.
`--vivado` selects its Windows installation path. AMD IP is discovered in the
local generated project and is not redistributed. Verilator cannot execute this
converter's encrypted FIFO implementation; it remains useful for the separate
renderer regressions.

The input inventory, header hashes, syntax normalizations, generated fixture
hashes, tool logs and pixel checks are retained in
[the validation directory](../validation/board-hp3/README.md).

## FPGA build status

The earlier endpoint candidate completed synthesis: 23,372 LUTs, 29,120
registers, 60.5 BRAM36 equivalents and 22 DSPs. That checkpoint predates these
four corrections. It retains debug-core placeholders and constraint lookup
warnings, so it is not ready for hardware installation.
[The scoped synthesis record](../validation/board-endpoint/pre-hp3-synthesis/result.json)
keeps it separate from the revised renderer. Synthesis, debug-core resolution,
constraint review and routed timing must be repeated for the corrected build
before physical GPU measurement.

The corrected project has since passed integration and XSA export. Its PS7
settings, address map and GPU aperture pass the topology audit. All eight
generated converter/vendor/header inputs match the tested inputs byte for byte.
Corrected full-board synthesis has completed and the checkpoint passed a fresh
Vivado audit (exit 0). It uses 23,368 LUTs, 29,120 registers, 60.5 BRAM36
equivalents and 22 DSPs: four fewer LUTs than the superseded candidate, with
the other counts unchanged. The audit found only the expected `dbg_hub` and
`u_ila_0` placeholders. The DRC report contains 41 warnings and one advisory.
See [the corrected synthesis record](../validation/board-hp3/synthesis/result.json).

This is an unrouted checkpoint. Its setup/hold estimates are −0.454/−0.374 ns;
602 clock pins and 1,032 internal endpoints lack timing coverage. These figures
are not timing signoff. Constraint lookup and debug warnings remain in the
archived logs. A [same-stage comparison](../validation/board-hp3/synthesis/comparison.json)
finds the same 602 unclocked audio pins and worst setup/hold margins in the
unchanged baseline; its unconstrained internal endpoint count is 1,034.
Optimization and debug-core implementation have now passed with exit 0 and
zero remaining black boxes. Wine again failed to start its generated debug
jobs; running their unchanged Tcl directly produced verified checkpoints for
both cores. The [optimization record](../validation/board-hp3/optimization/result.json)
retains the actual exits and source/checkpoint hashes.

The optimized design uses 27,499 LUTs (51.69%), 35,564 registers (33.42%),
80.5 BRAM36 equivalents (57.50%) and 22 DSPs (10%). Relative to the optimized
baseline, this is 382 more LUTs and 766 more registers, with BRAM/DSP counts
unchanged. These totals include debug instrumentation.

DRC still reports 41 warnings and one advisory, without errors. The critical
CDC groups match the baseline; the added peripheral/endpoint converter adds
five crossings in each direction, all classified safe. CDC analysis excludes
unclocked logic: 566 clock pins and 1,014 internal endpoints still lack timing
coverage. Pre-route setup/hold margins were −0.454/−0.374 ns. Routing has now
completed; the separate results below supersede those estimates.

Implementation continues in separate Vivado processes. These scripts accept
one Tcl argument: the isolated board directory containing `completion-synth.dcp`:

1. `audit-synth-board.tcl` reopens the checkpoint and checks the part, endpoint
   presence and expected debug placeholders, then reports DRC, clocks and timing.
2. `optimize-board.tcl` resolves debug cores through `opt_design`, rejects remaining
   black boxes and writes `completion-optimized.dcp` with fresh reports.
   `audit-optimized-board.tcl` can independently reopen that checkpoint and
   repeat its reports when the original process exit was not retained.
3. `route-board.tcl` places and routes that optimized checkpoint, retaining route,
   timing, DRC, methodology, CDC and bus-skew reports for review.

No script generates a bitstream or programs hardware. Existing optimization or
routed checkpoints are not overwritten. After an interrupted run has exited,
`route-board.tcl` accepts `--resume-placed` after the board directory. This
reopens `completion-placed.dcp`, repeats physical optimization and routing, and
skips placement. It does not treat an interrupted route as complete. The known Wine debug-runner workaround
in the [rebuild guide](../../../../docs/xacp-firmware-rebuild.md) may still be
required; a stalled debug job must not be marked successful without executing
its generated synthesis script and checking the new checkpoint.

The original synthesis wrapper disappeared while Vivado continued running.
Its original exit code therefore cannot be claimed. The local continuation
waits for Vivado to end, requires its completion marker and a nonempty checkpoint,
checks the staged source hashes, then runs the independent checkpoint audit.
That audit and optimization passed. After reviewing utilization, DRC, CDC and
unrouted timing, the separate placement/routing script completed with exit zero.
It retained reports and a checkpoint without generating or installing a bitstream.

## Routed result and timing work

All **55,980 routable nets** routed with zero routing errors. Setup timing fails:
WNS **−0.773 ns**, TNS **−19.821 ns**, 56 failing endpoints. Hold passes at
+0.009 ns with no failing endpoints. The worst path is the 100 MHz texture
sampler, from `step0_heightPow2minus1` to `texelAddr01`; it contains 16 logic
levels. This is a failed candidate, not a usable 100 MHz claim.

DRC retains 52 warnings and one advisory. Missing clocks, unconstrained paths
and the existing methodology findings remain. Bus-skew reports contain MET and
NA entries; NA is not a pass. [Routed evidence](../validation/board-hp3/routing/result.json).

`refine-route.tcl` completed physical optimization and rerouting without changing
clocks, RTL or timing exceptions. Setup still fails: WNS **−0.282 ns**, TNS
**−3.612 ns**, 31 failing endpoints. Hold remains +0.009 ns; all 55,985 nets
route without errors. [Refinement evidence](../validation/board-hp3/refinement/result.json).
Placement refinement alone did not remove the texture-address critical path.

The separate carry-free texture-address candidate replaces addition with OR
where the LOD base and coordinate fields are disjoint. It passes 4,096 field
combinations, 262,144 side-by-side sampler cycles, the full-renderer regression
and all 10 generated-HP3 converter tests (32 verified framebuffers). Full-board
synthesis and its independent checkpoint audit also passed. The synthesized
design uses 23,308 LUTs and 29,100 registers: 60 fewer LUTs and 20 fewer registers
than the corrected reference at the same stage. BRAM and DSP use are unchanged.
[Candidate evidence](../validation/texture-address/README.md). Debug-core
implementation and optimization have completed. A separate checkpoint audit
passed with exit zero and no black boxes. The optimized candidate retains
27,439 LUTs, 35,544 registers, 80.5 BRAM36 equivalents and 22 DSPs, including
debug cores. DRC findings, CDC summary groups and clock definitions match the
reviewed reference.

The carry-free candidate has now routed all **55,899 nets**, with zero routing
errors. Declared setup, hold and pulse-width constraints pass: **+0.055 ns setup**
and **+0.011 ns hold**, with zero failing endpoints. DRC, methodology and CDC
summary findings match the reference. Ten bus-skew NA rows and existing timing
coverage gaps remain; this is not complete timing signoff.
[Routed candidate evidence](../validation/texture-address/routing/result.json).
The bitstream and boot package have been generated and verified. A separate
steady-state check of the observed 1920x800 Workbench preset (125 MHz) passes
at +0.040 ns setup / +0.011 ns hold, with no PLL findings. Original PLL
properties were restored after analysis; no hardware clock was changed.
[Workbench mode evidence](../validation/texture-address/workbench125/result.json).
Physical GPU FPS remains unmeasured.
